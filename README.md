# Platon Masayuki — Bio

Статическая страница профиля. Для локального просмотра запустите из корня проекта:

```sh
python3 -m http.server 8000
```

Откройте `http://localhost:8000`. Для публикации достаточно разместить `index.html`, `styles.css`, `script.js` и папку `assets` на любом статическом хостинге.

Тексты, ссылки и блок кураторов находятся в `index.html`. Аватар и боковые иллюстрации — в `assets/img`. Текущий трек находится в `assets/audio/soft-nightcore.mp3`. Обрезанная версия ECLIPSER сохранена отдельно в `assets/audio/eclipser.mp3`. Перед публикацией убедитесь, что у вас есть права на использование трека. Для замены измените путь и название трека в `index.html`. Скрипт `tools/make_audio.py` позволяет создать альтернативный эмбиент без сторонних зависимостей.

Боковые изображения найдены в сети: [Гатс](https://www.pinterest.com/trisyiacujoh/guts-%2B-berserk-art/) и [Фемто](https://pinterest.com/ideas/griffith-femto-manga-panel/896164991026). Персонажи и изображения связаны с «Berserk»; перед публичным коммерческим использованием проверьте права на изображения. Аватар предоставлен владельцем страницы.

## Развёртывание на сервере

1. Настройте DNS-запись **A** для `masayuki.fun` на `92.124.130.182`. Если есть запись **AAAA**, она должна вести на тот же сервер по IPv6; иначе удалите её. Убедитесь, что DNS обновился и входящие TCP-порты 80 и 443 открыты. Для HTTP/3 также нужен UDP 443.
2. Установите Docker и Docker Compose на сервер, скопируйте проект и в его папке запустите:

   ```sh
   docker compose up -d --build
   ```

   Сам сайт будет доступен только на `127.0.0.1:8181` сервера; проверьте его командой `curl http://127.0.0.1:8181`. Порт 8181 должен быть свободен. При изменениях в файлах сайта нужно повторить `docker compose up -d --build`.

### Если Caddy уже работает на сервере

**Не запускайте второй Caddy** из этого проекта: два процесса не смогут одновременно занять порты 80 и 443 на одном IP. Добавьте новый блок в **существующий** Caddyfile, не удаляя блок `appela.ru`.

Если существующий Caddy установлен непосредственно на сервере (не в контейнере):

```caddyfile
masayuki.fun {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8181
}
```

Если существующий Caddy работает в Docker, `127.0.0.1` внутри него — сам контейнер, а не сервер. Подключите контейнер Caddy к сети сайта (название контейнера узнайте через `docker ps`):

```sh
docker network connect masayuki_bio_network ИМЯ_КОНТЕЙНЕРА_CADDY
```

После этого добавьте в его существующий Caddyfile блок:

```caddyfile
masayuki.fun {
    encode zstd gzip
    reverse_proxy masayuki-bio:80
}
```

Для постоянного подключения сети при пересоздании контейнера добавьте её как внешнюю сеть в Compose существующего Caddy. Убедитесь, что сеть `masayuki_bio_network` создана командой `docker compose up -d --build` этого проекта.

Сохраните копию старого Caddyfile, проверьте конфигурацию и перезагрузите **существующий** Caddy. Для установки как системной службы, если путь к конфигурации стандартный:

```sh
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

Для Caddy в Docker (замените имя контейнера и путь к файлу при необходимости):

```sh
docker exec ИМЯ_КОНТЕЙНЕРА_CADDY caddy validate --config /etc/caddy/Caddyfile
docker exec ИМЯ_КОНТЕЙНЕРА_CADDY caddy reload --config /etc/caddy/Caddyfile
```

Важно: изменения должны попасть в файл, который действительно смонтирован в контейнер. После проверки откройте `https://masayuki.fun`; Caddy автоматически запросит сертификат. Отдельный блок `appela.ru` продолжит обслуживаться существующим Caddy.

### Если Caddy на сервере ещё нет

Вместо приведённых выше шагов с существующим Caddy можно запустить включённый в проект вариант:

```sh
docker compose --profile standalone up -d --build
```

Он займёт порты 80 и 443 и использует `Caddyfile` из проекта. Сертификаты хранятся в Docker volume `caddy_data`. Этот вариант не предназначен для одновременного запуска с уже работающим Caddy на тех же портах.

### Добавление к существующей конфигурации с `http://:80`

Если ваш существующий Caddyfile начинается с блока `http://:80 { ... }`, **сохраните этот блок целиком**: он продолжит обрабатывать старый сайт. Не заменяйте его нашим отдельным `Caddyfile`. Запустите `bio` и подключите существующий контейнер Caddy к `masayuki_bio_network`, как описано выше. Затем добавьте **после закрывающей скобки** существующего блока один из следующих блоков.

Если этот Caddy сам принимает публичные запросы на 80 и 443 и должен выпускать HTTPS-сертификат:

```caddyfile
masayuki.fun {
    encode gzip zstd
    reverse_proxy masayuki-bio:80
}
```

Для этого публичные порты 80 и 443 должны попадать в этот контейнер (обычно в Compose нужны публикации `80:80` и `443:443`), DNS должен указывать на сервер, а порты — быть открыты. Caddy автоматически включит HTTPS и перенаправление для `masayuki.fun`. Существующий блок `http://:80` при этом остаётся HTTP; сам по себе он не настраивает HTTPS для `appela.ru`.

Если HTTPS уже завершается на другом прокси **перед** этим Caddy и тот передаёт исходный заголовок Host, вместо блока выше используйте HTTP-блок (и настройте `masayuki.fun` на внешнем прокси):

```caddyfile
http://masayuki.fun:80 {
    encode gzip zstd
    reverse_proxy masayuki-bio:80
}
```

Не добавляйте оба варианта одновременно. Какой вариант подходит, зависит от того, куда направлены публичные порты и где завершается TLS. После изменения проверьте и перезагрузите существующую конфигурацию, затем проверьте оба сайта. Если Caddy запускается не в Docker, используйте в соответствующем блоке `reverse_proxy 127.0.0.1:8181` вместо `masayuki-bio:80`.
